# ETN × RAPIRA — Telegram Mini App

В архиве находится проект мини-приложения и Telegram-бота. Баннеры рейтинга подключены из локальных файлов:
- `web/assets/etn-player-ranking.jpg` — баннер рейтинга игроков;
- `web/assets/etn-team-ranking.jpg` — баннер рейтинга команд.
- Баннеры показываются и во вкладках рейтинга, и на отдельных экранах «Топ игроков» и «Команды».

## Что находится в проекте
- `web/index.html` — интерфейс Mini App;
- `web/assets/` — баннеры;
- `app.py` — Flask API, проверка подписи Telegram Web App и хранение состояния в SQLite;
- `bot.py` — Telegram-бот с кнопкой открытия Mini App;
- `requirements.txt`, `Procfile` — запуск на Python-хостинге;
- `netlify.toml` — публикация статических файлов и проксирование `/api/*` на настроенный backend.

## Публикация
Публикация на аккаунтах пользователя не выполняется автоматически из этого архива: для неё нужен доступ к хостингу и настройкам Telegram-бота.

1. Загрузите содержимое архива в свой Git-репозиторий.
2. На Netlify создайте сайт из репозитория; каталог публикации — `web` (уже указан в `netlify.toml`).
3. Разверните Python backend из этого же репозитория на хостинге, который поддерживает постоянный процесс и постоянный диск для SQLite. Команда запуска веб-сервиса указана в `Procfile`.
4. Установите переменные окружения на backend: `BOT_TOKEN`, `ADMIN_IDS`, `ETN_DB_PATH`. Не публикуйте токен в репозитории.
5. В `netlify.toml` замените адрес `http://bot-1792340572-2257-mid.bothost.tech` на HTTPS-адрес вашего backend, затем повторно опубликуйте сайт.
6. В настройках процесса Telegram-бота задайте `BOT_TOKEN` и `WEBAPP_URL` (публичный HTTPS-адрес сайта), затем запустите процесс `worker: python bot.py`.
7. Откройте бота в Telegram и отправьте `/start`. Кнопка откроет Mini App.

## Важно
- `WEBAPP_URL` должен быть публичным HTTPS-адресом.
- `BOT_TOKEN` храните только в секретах хостинга.
- Если backend уже размещён, используйте его настоящий адрес вместо примера в `netlify.toml`.
- Перед запуском проверьте `/health` у backend и откройте Mini App из Telegram, чтобы API-запросы шли с корректным `initData`.

## Создание команд ETN (v14)

- Тестовые/бета-команды и демонстрационный профиль команды убраны из интерфейса.
- Создание команды находится в разделе **Профиль → Создать свою команду**.
- Капитан должен открыть Mini App из Telegram и иметь Telegram username.
- Каждый участник указывается через Telegram username и должен запустить бота командой `/start`, чтобы попасть в реестр пользователей ETN.
- Сервер проверяет регистрацию всех участников, уникальность названия и то, что участник ещё не состоит в другой команде.
- Команды хранятся в общей SQLite-базе сервера в таблице `teams`, а список отображается в разделе **Команды**.
- Для совместной работы бота и веб-приложения переменная `ETN_DB_PATH` должна указывать на один и тот же постоянный файл SQLite для обоих процессов.
- После обновления нужно перезапустить веб-сервис и убедиться, что `BOT_TOKEN`, `WEBAPP_URL` и постоянный `ETN_DB_PATH` настроены в окружении.


## Версия 18 — серверная админ-панель

В админ-панель добавлены серверная проверка Telegram ID, сводка, список зарегистрированных пользователей, управление командами, модерация матчей/заявок организаторов/регистраций со скриншотом, управление турнирами, BAN-лист, серверные обращения поддержки, настройки бота/платформы, журнал изменений и экспорт/импорт состояний.

**ID владельца уже добавлен в проект:** `5686836766` и `5728174980` включены в `ADMIN_IDS` в `app.py`, а также указаны в `env.example`. Поэтому этот Telegram-аккаунт считается администратором даже если переменная `ADMIN_IDS` на хостинге ещё не настроена. При этом API всё равно требует действительную Telegram `initData`, проверяемую с помощью `BOT_TOKEN`. Для запуска необходимо настроить настоящий `BOT_TOKEN`, постоянный `ETN_DB_PATH` и HTTPS-адрес backend в `netlify.toml`. Если укажешь других администраторов, впиши их числовые ID через запятую в переменную `ADMIN_IDS` на хостинге; встроенный ID владельца останется разрешённым.

Настройки управления ботом сохраняются в общей SQLite-базе; процесс бота читает состояние активности/техработ и текст приветствия при команде `/start`. Некоторые флаги заявок дополнительно необходимо применять на соответствующих серверных маршрутах, прежде чем считать их полностью enforced. Созданные на сервере турниры и BAN-записи хранятся централизованно; перед публичным запуском подключи публичные формы/экраны заявок и проверку BAN к серверным endpoint, чтобы ограничение работало не только в интерфейсе.


### Какие действия защищены сервером в v18

- Административные API требуют валидную Telegram `initData` и числовой Telegram ID из `ADMIN_IDS`. Локальный PIN не открывает серверные данные.
- Очереди заявок пользователей работают в режиме добавления: обычный пользователь не может переписать существующую заявку или изменить её статус; модерация выполняется через защищённый admin API.
- `registrations` выключает серверное создание команд; серверный BAN блокирует создание команды у забаненного аккаунта и запрещает добавлять забаненного участника в новую команду.
- Обращения, отправленные через `/api/support-tickets`, попадают в общую очередь поддержки. Резервная копия включает управляемые состояния, список команд, пользователей и журнал действий.
- Заявки на участие в турнирах передаются в общую серверную очередь через append-only состояние, а сервер блокирует отправку заявки с Telegram-аккаунта, на котором активен BAN. Осталось связать каждого игрока пользовательского состава со своим Telegram ID, чтобы BAN другого участника состава проверялся независимо от капитана.
- Флаги `organizerApplications`, `tournamentApplications`, `enabled`, `maintenance` и `supportEnabled` проверяются на соответствующих серверных маршрутах для новых заявок и обращений.

- Заявки на участие в турнирах синхронизируются через append-only серверное состояние; сервер не разрешает обычному пользователю менять статус уже существующей заявки и отклоняет новую заявку от аккаунта с активным BAN.

## Администраторы ETN/RAPIRA

- Главный администратор: Telegram ID `5728174980`.
- Добавление и отзыв доступа коллег доступны во вкладке «Администраторы» внутри серверной панели.
- Список хранится в SQLite-таблице `admins`; для совместной работы между устройствами хостинг должен использовать постоянный диск и одинаковый `ETN_DB_PATH` (по умолчанию `/data/etn.sqlite3`).
- В настройках хостинга задайте `ADMIN_SETUP_PIN` как длинный случайный секрет и `BOT_TOKEN`. PIN сохраняется в базе только в виде SHA-256-хеша и одноразовая операция `/api/admin/setup-pin` может быть выполнена только главным администратором.
- Не используйте временную файловую систему хостинга для базы, иначе список администраторов потеряется после пересоздания контейнера.


## Исправление отображения PIN в меню
Форма одноразового PIN админ-панели закреплена отдельной второй строкой нижнего меню Mini App, поэтому она не обрезается из-за сетки из 7 навигационных кнопок. Для публикации достаточно заново задеплоить `web`.
